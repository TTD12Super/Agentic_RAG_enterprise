## Implemented boundary

- Upload manifest validation for private `.pdf`, `.docx` and `.xlsx` sources,
  200,000,000-byte limit, checksum, MIME/signature and INTERNAL department
  requirements.
- Quarantine before processing, clean-scan gate, independent review-1 and
  review-2 decisions, approval expiry and idempotent approval keys.
- Provider-neutral processing input using KNOW-001 chunk metadata; parent ACL
  inheritance is enforced and child broadening/no-ACL chunks fail closed.
- Derived index staging with content checksum, chunk digest, ACL digest,
  generation, fencing token and explicit ACK before publication.
- Atomic in-memory authority transition to ACTIVE; previous ACTIVE becomes
  SUPERSEDED only after the new index is prepared.  Publication failure keeps
  the previous ACTIVE version serving and cleans the new projection.
- Retrieval gate checks authoritative document status/current version,
  ACTIVE version state, PUBLISHED index state and ACTIVE chunk state.  A
  derived index cannot grant access by itself.
- Revoke, soft delete and permanent delete isolation.  Permanent delete is
  blocked by retention/legal hold; derived cleanup is tracked for retry.
- Bounded unchanged-checksum retry with unique attempt IDs and a three-attempt
  limit; invalid scan/chunk input is terminal.
- Maintenance ACTIVE/RELEASED/FAILED/EXPIRED states, watchdog expiry without
  auto-approval, cleanup and explicit recovery.  Query-job pause/resume remains
  owned by CHAT-001 as required by the contract.
- Optional injected audit sink using the existing redacted audit boundary.

## Scope and integration limits

- No Alembic migration was required; the implementation is an in-memory
  authority test double and explicitly leaves the existing DB-001 schema
  ownership with Backend.
- No real object storage, parser/OCR, Qdrant, queue, cloud, API key or model
  provider was used.
- The production adapter must persist these transitions in PostgreSQL and use
  an outbox/reconciliation worker for derived-index cleanup before production
  readiness can be claimed.
- Retrieval authorization is intentionally not implemented here; callers must
  still invoke the existing PDP/PEP before serving chunks or source files.
- CHAT-001 must own query pause/resume and re-check authorization/version state
  after maintenance recovery.
