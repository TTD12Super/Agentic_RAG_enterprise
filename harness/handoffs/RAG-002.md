# RAG-002 handoff

## Outcome

`ACCEPTED — MAIN AGENT REVIEW COMPLETE`

Added deterministic/local hybrid retrieval for the in-memory evaluation path:

- BM25 with configurable `k1=1.5` and `b=0.75`.
- Reciprocal-rank fusion with default `rrf_k=60`.
- Provider-neutral reranking through the existing `ModelGateway` boundary.
- A deterministic local token-overlap reranker adapter for offline tests.
- Hybrid source fetch delegates to the RAG-001 dense retriever, preserving its final authorization check.

The BM25 branch checks each candidate through `DenseRetriever.is_authorized` before scoring. That reuses the RAG-001 tenant, index `ACTIVE`, current document/version `ACTIVE`, ingestion publication, ACL/PEP and policy-epoch checks; denied, cross-tenant, superseded and staging candidates remain absent from hybrid results.

## Scope limits and approval boundaries

- This is a deterministic in-memory implementation only. Qdrant, persistence, production lexical indexes, API/orchestration wiring, parent expansion, query rewriting, citation-token issuance and full Golden Dataset evaluation remain out of scope.
- The local reranker is a test/offline double, not evidence that a production cross-encoder or threshold is approved.
- Scores are ranking signals, not correctness probabilities.
- The tiny corpus metrics are regression evidence, not production quality or latency guarantees; project thresholds remain owner-approved decisions.
- The evaluation test imports now work from the repository root; no runtime
  dependency or production behavior was changed by that small test-harness fix.
- `graphify update .` was not run because the user limited writes to the RAG, test and handoff paths; updating `graphify-out/` would exceed that boundary.
- Main accepted the deterministic local scope. Production reranker/model
  selection, Qdrant integration and any contract/authorization ownership
  change still require separate review.
