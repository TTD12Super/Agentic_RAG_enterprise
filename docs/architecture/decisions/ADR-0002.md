# ADR-0002 — Core-owned authorization across Rust and Python

- Status: Accepted
- Date: 2026-11-09
- Affected: identity, authorization, retrieval, tools, source access, cache, queue

## Context

The vector index, LLM, browser, queue message and retrieved document text are untrusted with respect to access decisions. Python workers need current policy decisions while the Core remains the trusted authority.

## Decision proposal

Use a trusted backend PDP in the Core with PEPs at each relevant trust boundary. For the MVP, the Core is Python/FastAPI; the Rust/Python trust boundary remains a future benchmark/migration concern:

- API and job acceptance/resume.
- Tool Gateway and every dense/lexical retrieval branch.
- Chunk/parent expansion, citation and original-source access.
- Conversation, retrieval and answer-cache reuse.

Workers receive an opaque, policy-versioned scope or perform an approved policy recheck. The mechanism for authenticated Rust-to-Python policy calls remains pending a contract and security review. The LLM may describe rules but can never grant access.

## Consequences

- Fail closed on missing principal, stale scope, policy outage or unknown classification.
- Revocation must affect queued, resumed, cached and citation operations.
- Scope and worker-authentication contracts become cross-runtime integration gates.
- Role/department/document ACL precedence and Chairman/Admin exceptions remain owner policy decisions.

## Approval

Project Owner approved this ADR as the MVP authorization baseline on 2026-11-10. The detailed authorization matrix and Rust/Python trust-interface contract remain subject to their affected contract/security gates.

## Owner-provided policy alignment

- Authorization combines RBAC, department membership and document-level ACLs with default deny.
- Explicit deny overrides role allow; Chairman's broad read capability does not bypass an explicit deny.
- Workers use short-lived service identities and must recheck tenant, ACL, policy version and document version when running, resuming, reading chunks or returning citations.
- System Admin may operate the system but must not automatically read user conversation bodies.
- Product classification is `PUBLIC`/`INTERNAL` for MVP. Provider-egress policy reserves stricter future handling for unknown or higher-sensitivity data.
