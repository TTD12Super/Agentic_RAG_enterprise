# ADR-0001 — Rust Core + Python workers within a modular product

- Status: Accepted
- Date: 2026-11-09
- Affected: backend runtime, workers, deployment, repository ownership

## Context

The overview now describes a modular monolith core with independent RAG and ingestion workers. The product needs trusted API, identity, authorization, administration and job coordination, while Python libraries remain useful for retrieval, parsing and model orchestration.

## Options

1. Keep one Python/FastAPI runtime for all work.
2. Split every logical block into microservices.
3. Use a modular Core with independently scaled Python RAG and ingestion workers.

## Decision proposal

Use option 3 as the target architecture to evaluate: a Rust Core candidate owns API, identity, authorization, administration, document lifecycle, chat jobs, maintenance, scheduling and audit visibility; Python workers own RAG, evidence, LangGraph, model gateway and document processing.

This is not permission to move the current repository or approve Rust/Axum/Tokio. The current layout remains authoritative until a benchmark, migration plan and owner approval exist. The 17 blocks remain logical capabilities, not network services.

## Consequences

- Rust and Python communicate only through versioned, authenticated contracts.
- Workers scale independently without becoming autonomous policy authorities.
- A Python/FastAPI baseline remains a useful comparison for the Rust trial.
- More operational boundaries exist: queue delivery, worker authentication, retries and schema compatibility must be tested.
- No microservice split is justified without measured bottleneck or trust-isolation evidence.

## Approval

Project Owner approved this ADR as the MVP architecture baseline on 2026-11-10. The Rust candidate, benchmark scope and any repository migration remain separately gated by the still-pending decision register items.

## Owner-provided MVP alignment

- MVP backend remains Python/FastAPI modular monolith with separate Python RAG and ingestion workers.
- Rust Core remains a benchmark-gated candidate, not an approved repository migration.
- The benchmark must compare API throughput, p95 latency, resource use and operational complexity before any runtime switch.
- PostgreSQL 17, Qdrant, private S3-compatible object storage and optional Redis are the current proposal stack.
